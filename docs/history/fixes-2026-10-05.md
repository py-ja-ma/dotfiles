# 2026-10-05 — what was changed on both machines

## cabin

**Would not boot after a motherboard swap and an NVMe slot move.** Two independent faults:

1. GRUB had been installed with `grub-install --removable`, which writes only
   `\EFI\BOOT\BOOTX64.EFI` and creates **no NVRAM entry**. The old board tried that
   fallback path on a fixed disk; the new one did not. `BootOrder` additionally led with
   legacy-CSM `BBS(HD,...)` entries and a stale Windows Boot Manager entry pointing at a
   `bootmgfw.efi` whose OS partition no longer exists.
2. The initramfs was built against the old motherboard. `HOOKS` contains `autodetect`,
   which strips every storage module not present at build time.

Fixed by `grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB`
(creating `Boot0001* GRUB`), a `--removable` refresh for belt and braces,
`grub-mkconfig`, and `mkinitcpio -P` in-chroot against the new hardware. Verified
`nvme.ko.zst` present in both images before rebooting. Full runbook:
`docs/boot-recovery.md`.

**Was ~4 months stale.** 638 packages pending; `linux` 7.0.11→7.2.8, `linux-lts`
6.18.35→6.18.55, `systemd` 260→262, `glibc` 2.43→2.44, `grub` 2.14→2.16, `mkinitcpio`
41→42.2, nvidia 610.43.02→615.71.09. The upgrade was **blocked** by two version-pinned
AUR packages:

```
:: installing audit (4.2.1-1) breaks dependency 'audit=4.1.4' required by lib32-audit
:: installing qemu-common (11.1.1-4) breaks dependency 'qemu-common=11.0.1-1' required by qemu-block-gluster
```

Cleared with `pacman -Rdd` on each (removing only the pinning package, no cascade).
`qemu-full 11.1.1-4` no longer depends on `qemu-block-gluster` at all, so that one is
simply gone. **`lib32-audit` has not been rebuilt** — `lib32-pam` has an unsatisfied
dependency. See `docs/arch-upgrade.md`.

Post-upgrade: re-ran `grub-install` (the 2.14→2.16 bump left a stale ESP binary against
2.16 modules — a real boot hazard), enabled a persistent fallback initramfs via
`PRESETS=('default' 'fallback')` in `/etc/mkinitcpio.d/linux-lts.preset`, confirmed DKMS
built nvidia for both kernels. Rebooted clean on `6.18.55-1-lts`, 0 failed units.

**Deleted `~/Games/ascension-wow`** (50 G wine prefix, servers shut down),
preserving only `WTF/` (66 files of character/UI settings). The 228 "screenshots"
found during inspection were ElvUI addon media, not personal screenshots.

## panasonic

**Hyprland would not start.** Root cause was not graphics — see
`hosts/panasonic/README.md` for the full chain. Summary: `systemd-networkd-wait-online`
timed out on a carrier-less ethernet link, delaying `graphical.target` to +2 min 03 s,
and `uwsm start` hard-gates on it.

Applied: a `--any --timeout=20` drop-in (`graphical.target` now @11.5 s), disabled the
duplicate `ly@tty1` greeter, restored `getty@tty1`, removed two 0-byte orphan files, and
added a LAN-scoped SSH rule to nftables.

### One error worth recording

The first attempt at the drop-in wrote the **sudo password** into
`/etc/systemd/system/systemd-networkd-wait-online.service.d/any.conf`. Cause: a helper
of the form `echo "$PW" | sudo -S tee <file> <<'EOF' ... EOF` — the `echo` pipe wins over
the heredoc, so `tee` wrote the password instead of the config. The fix never applied and
a credential landed in a root-owned file for ~4 minutes. Scrubbed and verified with
`grep -rl` across `/etc`.

**Lesson:** never feed a sudo password through the same stdin a heredoc needs. Stage the
file as the user, then `sudo cp` it into place.

### cabin: Hyprland config errors (same day, after the upgrade)

`hyprland` 0.56 rejected two directives in cabin's legacy `~/.config/hypr/hyprland.conf`:

```
line 188: config option <dwindle:pseudotile> does not exist
line 251: Invalid dispatcher, requested "togglesplit" does not exist
```

Resolved by probing the running compositor rather than guessing:

| probe | result |
|---|---|
| `hyprctl dispatch layoutmsg togglesplit` | `ok` — the replacement |
| `hyprctl dispatch togglesplit` | `Invalid dispatcher` |
| `hyprctl dispatch pseudo` | `ok` — bare dispatcher still valid |
| `hyprctl dispatch layoutmsg pseudo` | `Unknown dwindle layoutmsg` |

So: `dwindle:pseudotile` was removed as a config option (pseudotiling is per-window now
via the still-valid `pseudo` dispatcher), and `togglesplit` moved under `layoutmsg`.
Fixed both, `--verify-config` returns `config ok`, applied with `hyprctl reload`.
Backup at `~/.config/hypr/hyprland.conf.bak-20261005-confix`.

Note this is cabin's **own legacy config**, not the rice. It is replaced wholesale when
the Home Manager flake is applied to cabin.

Order of operations, each verified before the next:

1. 60 repo packages via a detached `systemd-run` unit (0 errors). `refind` and
   `plymouth` landed here; note `refind-install` did NOT run — the pacman hook is
   user-made on panasonic, so the repo now ships it as `system/99-refind.hook`.

   `.install`, no network fetches). Build deps installed as root first so `makepkg`
   never needed sudo.
3. 17 AUR packages. Two unattended attempts failed before the mechanism was right:
   a `&`-backgrounded ssh got hung up by the tool shell, then sudo's **per-tty**
   timestamp made a tty-less `sudo pacman` prompt and die. The fix is an askpass
   helper (`SUDO_ASKPASS` + `paru --sudoflags=-A`) whose script prints an

4. Home Manager switch (`pj@cabin`) — hypr/kitty/rofi/swaync/themes became live

6. rEFInd: `refind-install` (NVRAM `Boot0008`, GRUB kept as `Boot0001`), theme via

## cabin: first boot on the new chain, and the rEFInd menu

First reboot came up clean: `BootCurrent 0008` (rEFInd), LTS kernel, `nvidia_drm`
modeset on, no nouveau, Plymouth ran, `graphical.target` at 2.9 s, 0 failed units,
Hyprland loaded the Lua config with 68 binds and workspaces 1-9 persistent, one
waybar, swaync only, and every NVIDIA/shader-cache variable present in the
compositor's environment.

Two things were wrong with the menu. The theme's `hideui` included `label`, so the
five icons had no text. And `scanfor` was at its default, so rEFInd listed both
kernels, both recovery stanzas, the leftover Windows loader, and GRUB's loader —
and it was GRUB it chainloaded on that boot (the kernel received GRUB's cmdline with
no `initrd=`), which is why the splash did not show. Fixed: `scanfor manual`, exactly
two stanzas ("Arch Linux", "Arch Linux (recovery)"), `default_selection`, `timeout 10`,
and `label` removed from `hideui` in both the ESP theme and `system/refind-catppuccin/`.
GRUB remains installed with its NVRAM entry as the firmware-menu fallback. The
pre-Plymouth insurance image was dropped once the new images had booted.

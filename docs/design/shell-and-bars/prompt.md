# Prompt

[Design](../README.md) › [Shell & bars](README.md) › Prompt

starship draws the prompt from one file, `dotfiles/.config/starship.toml`, on the Arch hosts, in the WSL clones and in PowerShell on Windows.
It is set in words and named ANSI colors, with no hostname, no OS logo and no icon glyph, so each terminal theme recolors it.

| | |
|---|---|
| Code | `dotfiles/.config/starship.toml`; on Arch `modules/shell.nix` and `modules/cli.nix`; on Windows the profile in `install/windows/dram-windows/look.ps1`, the units `starship-config` and `powershell-5-profile-policy` in `windows/roles/base.nix`, and `install/windows/letterpress/psreadline.ps1`, generated by `bin/gen-windows-look.py` |
| Runs on | bash on each Arch host and WSL clone; PowerShell 7 and Windows PowerShell 5.1 on cabin-win |
| Needs | starship 1.26.0 from nixpkgs, tested 2026-10; on Windows winget's `Starship.Starship`, unpinned; a terminal's 16 colors and a font with `❯` |
| Decided in | the prompt on Windows as on Arch ([decided 2026-10-12](../../../decisions/log.md#d86)); ble.sh removed on 2026-10-10 under [the software rules](../../../decisions/0013-software-rules-and-waivers.md) |

## How it works

### On Arch

`programs.starship` in `modules/shell.nix` installs starship and adds its hook to `~/.bashrc`.
`modules/cli.nix` links `~/.config/starship.toml` to the file in the repo on each host, the WSL clones included, so an edit shows at the next prompt.
The prompt has two lines: the words on line 1, and `❯` alone on line 2, so a typed command starts in the same column whatever line 1 holds.
`add_newline = false` drops the blank line starship puts above a prompt.
`command_timeout = 500` cuts off a command that takes longer than 500 ms, so a slow module cannot hold up the prompt.
The format names each module it draws, so no other module runs, and ten modules, the OS logo among them, are switched off by name as well.

Each style names an ANSI color (`bold green`, `italic blue`, `dimmed white`), and the file holds no hex color, so the terminal's 16 colors decide the inks.
In kitty those come from the active theme, and `dram theme` reloads kitty, so the prompt changes with the theme.
kitty sets the italic segments in Monaspace Radon.

### On Windows

winget installs PowerShell 7 and starship in the base role (`packages/winget/base.txt`).
`windows/roles/base.nix` stages `starship.toml` byte for byte at `C:\ProgramData\dram\starship.toml`, and its unit `starship-config` sets the user's `STARSHIP_CONFIG` to that path.
`look.ps1` writes one profile to `Documents\PowerShell\profile.ps1` for PowerShell 7 and to `Documents\WindowsPowerShell\profile.ps1` for 5.1, and each converge writes it again when it differs.
In a console host the profile sets UTF-8 output, sets `STARSHIP_CONFIG` when the environment lacks it, runs `starship init powershell`, and dot-sources `C:\ProgramData\dram\letterpress\psreadline.ps1`.
Local additions go in `profile.local.ps1` beside the profile, which it dot-sources last.
The unit `powershell-5-profile-policy` sets the execution policy of Windows PowerShell 5.1 to `RemoteSigned` for the user, so 5.1 runs the profile, as PowerShell 7 does by default.
Windows Terminal hosts both shells, in washi's scheme ([Terminal](terminal.md#windows)).

### PSReadLine's colors

`bin/gen-windows-look.py` writes `install/windows/letterpress/psreadline.ps1` from washi, with the syntax inks of the [VSCodium themes](../../../dotfiles/.vscode/extensions/letterpress-themes/README.md).
A color that is one of the scheme's 16 is written as a named ANSI color, and any other as 24-bit.
The file sets the prediction colors only where the loaded PSReadLine has them: 2.1 for the inline prediction, 2.2 for the list.
It turns PSReadLine's bell off.

| Token | Ink | In washi |
|---|---|---|
| keywords, emphasis | the accent | ANSI red, `31` |
| strings | ochre, the editor's string ink | ANSI yellow, `33` |
| types | blue | ANSI blue, `34` |
| commands | teal | `#89a186` |
| parameters, the continuation prompt | subtext | `#ac9c92` |
| numbers | the accent's second step | `#cb705b` |
| comments | subtext, italic | `#ac9c92` |
| errors | bright red | ANSI bright red, `91` |
| selection | `surface1` behind the text | ANSI bright black, `100` |
| default text, variables, members, operators | the body ink | ANSI white, `37` |
| the inline prediction, from PSReadLine 2.1 | overlay | `#716158` |
| the prediction list, from PSReadLine 2.2 | ochre, the selected line on `surface0` | ANSI yellow, `#2e211a` behind |

In PowerShell 7 the file also sets `$PSStyle`: directories blue, links cyan, executables green, table headers in italic subtext, format accents in subtext, verbose output in overlay, warnings yellow and progress in the accent.

## Reading the prompt

Line 1 holds only the segments that have something to show, in this order:

```text
pj .../dotfiles on master [⇡2!1] via node v24.21.0 sh 2 exit 127
❯
```

| Segment | Module | When it shows | Style |
|---|---|---|---|
| `pj` | `username` | on each prompt (`show_always`), in bold red for root | bold green |
| `.../dotfiles` | `directory` | the last four parts of the path, cut at the repository's root inside a git repository, with `.../` where it was cut; ` ro` follows a read-only directory | italic blue, `ro` in yellow |
| `on master` | `git_branch` | inside a repository, with `:<remote branch>` when the tracked branch has another name | italic yellow |
| `[⇡2!1]` | `git_status` | counts: `⇡` ahead, `⇣` behind, `=` conflicted, `+` staged, `!` modified, `>` renamed, `x` deleted, `?` untracked, `*` stashed | yellow |
| `(REBASING 2/5)` | `git_state` | during a rebase, merge, revert, cherry-pick or bisect, with the progress where git has it | bold red |
| `via node v24.21.0` | `nodejs` | in a directory with `package.json`, `node_modules`, or JavaScript or TypeScript files | green |
| `via py v3.14.8` | `python` | in a directory with Python files, with the virtual environment's name | yellow |
| `via nix impure` | `nix_shell` | inside a Nix shell, `pure` or `impure`, with its name | cyan |
| `sh 2` | `shlvl` | in a shell inside a shell, from a `SHLVL` of 2 | yellow |
| `&1` | `jobs` | while jobs run in the background, with their count | blue |
| `exit 127` | `status` | after a command that failed, with its exit code: 127 for a command not found, 130 for Ctrl-C | bold red |

`[⇡2!1]` reads as two commits to push and one modified file.
The `❯` on line 2 is bold green after a command that succeeded and bold red after one that failed.
There is no hostname: a host reached over SSH draws its own prompt.

`right_format` puts three more segments at the right end of line 1.
They are `took 3s` after a command that ran 2 s or more, `bat 20%` in bold red at 30 % battery or less (`bat+` while charging), and the time the prompt was drawn, `14:05`, in dimmed white.
bash draws a right prompt only through ble.sh, which left the hosts on 2026-10-10 under the Community rule of [the software rules](../../../decisions/0013-software-rules-and-waivers.md).
starship draws no right prompt in PowerShell either, so neither shell shows the three.
The setting stays for the shells that draw it, zsh and fish among them.

## No icon glyphs

`starship.toml` holds no private-use codepoint, so the prompt needs no Nerd Font.
Where other prompts put an icon, it puts a word: `on`, `via node`, `exit`, `ro`, `bat`.
Its only characters outside ASCII are `❯`, `⇡` and `⇣`, and the em dashes in its comments.
Monaspace 1.400 has `❯` and lacks `⇡` and `⇣`, so kitty and Windows Terminal take those two from a fallback font.
The check runs on Arch, whose grep has `-P`:

```sh
grep -cP '[\x{E000}-\x{F8FF}\x{F0000}-\x{FFFFF}]' dotfiles/.config/starship.toml   # prints 0
```

No section of `bin/check.sh` runs it; the bar's own glyph check is `bin/check-waybar.py`.

## Use it

```sh
starship explain     # each segment on screen: what it is and how long it took
starship timings     # how long each module took
```

On Arch, an edit to `dotfiles/.config/starship.toml` shows at the next prompt, since the file is linked.
To take a change to Windows:

1. Edit `dotfiles/.config/starship.toml`.
   For PSReadLine's colors, edit washi's palette files and run `python3 bin/gen-windows-look.py`.
2. Run `bin/render-windows.sh cabin-win`, since both are Windows render inputs, and commit the render.
3. Run `bin/push-windows.sh cabin-win --apply`, which needs a clean tree.
4. The next prompt in PowerShell reads the new file, and a new PowerShell window loads the new colors.

## Copy it alone

1. Install starship; 1.26.0 is the version tested, in 2026-10.
2. Copy `starship.toml` to `~/.config/starship.toml`, or point `STARSHIP_CONFIG` at it wherever it is.
3. Add the hook to the shell: `eval "$(starship init bash)"` at the end of `~/.bashrc`, or `Invoke-Expression (& starship init powershell)` in a PowerShell profile.
4. Set the terminal's 16 colors to the palette you want: the file names ANSI colors, and the terminal decides what they look like.
5. Open a new shell and run `false`.
   It worked when line 1 shows your user name, the directory and `exit 1` in red, and the arrow on line 2 turns red.
   Through starship's zsh or fish hook, the duration, a low battery and the clock show at the right as well.

## When it breaks

| Symptom | Check | Fix |
|---|---|---|
| PowerShell shows its stock `PS C:\>` prompt | `Get-Command starship` finds nothing, or in 5.1 `Get-ExecutionPolicy -Scope CurrentUser` is not `RemoteSigned` | `dram apply` in an elevated PowerShell installs starship and sets the policy |
| a segment is missing in a large repository | starship warns that a command timed out, and `starship timings` names the module | raise `command_timeout` in `starship.toml` |

## Limits

- bash and PowerShell draw no right-hand side, so the duration, the battery and the clock do not show ([Reading the prompt](#reading-the-prompt)).
- Without a hostname, a WSL clone's prompt looks the same as cabin's.
- cmd keeps its own prompt: starship would need Clink there, which is not installed.
- PSReadLine's 24-bit inks are washi's: another scheme picked in Windows Terminal changes the named colors and leaves those.
- Nothing runs the glyph check ([No icon glyphs](#no-icon-glyphs)).
